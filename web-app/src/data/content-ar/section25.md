## 1. ملخص Next.js

غطت الدورة، بالترتيب:

- **أساسيات App Router** (الأقسام 3–5) — التوجيه القائم على الملفات، التخطيطات، القطاعات الديناميكية
- **مكونات الخادم مقابل مكونات العميل** (القسم 6) — النموذج الذهني الأساسي للإطار بأكمله
- **التنسيق، الأصول، البيانات الوصفية** (الأقسام 7–8) — `next/font`، `next/image`، Metadata API
- **البيانات** (الأقسام 9–13) — الجلب، التخزين المؤقت/إعادة التحقق، Server Actions، Route Handlers، معالجة الأخطاء

- **أربعة مشاريع تطبيقية** (الأقسام 21–24) — مدونة، لوحة تحكم، تطبيق CRUD، متجر مصغر

## 2. أسئلة مقابلات شائعة حول Next.js

تدرّب على شرح ما يلي بأسلوبك الخاص:

- ما الفرق بين Server Components وClient Components، ومتى تحتاج إلى `"use client"`؟
- اشرح طبقات التخزين المؤقت الأربع في Next.js وكيف تتفاعل `revalidatePath`/`revalidateTag` معها
- لماذا تكون `params` و`searchParams` غير متزامنتين (async) في الإصدار الحالي من Next.js؟
- متى تستخدم Route Handler بدلاً من Server Action؟
- كيف يقرر Next.js ما إذا كان المسار يُعرض بشكل ثابت أم ديناميكي؟

## 3. Next.js مقابل React Router

| | Next.js (App Router) | React + React Router |
|---|---|---|
| التوجيه | قائم على الملفات، مدمج | مسارات تعريفية تحددها في الكود |
| العرض (Rendering) | Server Components افتراضيًا، البث (streaming)، ثابت/ديناميكي | من جانب العميل فقط (ما لم يُقترن بإعداد SSR منفصل) |
| جلب البيانات | مدمج في الإطار (مكونات خادم `async`) | لا يوجد اصطلاح مدمج — عادةً مكتبة منفصلة |
| الخلفية (Backend) | Route Handlers + Server Actions مضمّنة | لا يوجد — يحتاج API منفصل |

يُعد React Router الأداة المناسبة عندما تريد تطبيق صفحة واحدة (SPA) خالصًا من جانب العميل مع تحكم كامل ودون الحاجة إلى عرض من جانب الخادم. أما Next.js فهو الأداة المناسبة عندما تريد أن يتولى إطار عمل متكامل واحد التوجيه واستراتيجية العرض ومنطق الخلفية.

## 4. Next.js مقابل Remix

كلاهما إطارا عمل React متكاملان (full-stack) بفلسفات متشابهة (أولوية الخادم، التوجيه المتداخل)، ويختلفان بشكل رئيسي في اصطلاحات تحميل البيانات:

- **Next.js** — مكونات خادم `async` تجلب البيانات مباشرة داخل المكون؛ وتتعامل Server Actions مع التعديلات
- **Remix** — دوال `loader`/`action` لكل مسار تتعامل مع جلب البيانات والتعديلات، بنموذج تخزين مؤقت مختلف قليلًا

كلاهما خياران قويان؛ يمتلك Next.js نظامًا بيئيًا أكبر وتكاملًا مباشرًا مع استضافة Vercel.

## 5. المسار المهني لـ Next.js

تغذي مهارات Next.js مباشرة أدوارًا مثل:

- **مهندس واجهة أمامية (Frontend Engineer)** — بناء واجهة المنتج باستخدام إطار عمل، وليس مجرد مكتبة مكونات
- **مهندس متكامل (Full-Stack Engineer)** — بما أن Next.js يُضبب الحد الفاصل بين الواجهة الأمامية والخلفية عبر Server Actions وRoute Handlers
- **متخصص React/Next.js** — فرق استشارية أو منصات توحّد هذه الحزمة التقنية

---

## 6. ماذا تتعلم بعد Next.js

- **التخزين المؤقت المتقدم / Cache Components** — تحكم أعمق في العرض المسبق الجزئي (partial pre-rendering) وحدود التخزين المؤقت
- **الاختبار (Testing)** — اختبارات المكونات (Vitest/Testing Library) واختبارات شاملة (Playwright) لتطبيقات App Router
- **المستودعات الأحادية (Monorepos)** — هيكلة عدة تطبيقات/حزم Next.js معًا (Turborepo، Nx)
- **أدوات وكلاء الذكاء الاصطناعي (AI-agent tooling)** — يُدخل Next.js 16.3 (معاينة) ميزات موجهة نحو وكلاء الذكاء الاصطناعي تستحق المتابعة مع استقرارها

## 7. أفكار مشاريع نهائية

بالإضافة إلى المشاريع الأربعة المبنية في هذه الدورة، فكّر في:

- تطبيق **SaaS متعدد المستأجرين (multi-tenant)** مع عزل بيانات لكل منظمة
- أداة **تعاون في الوقت الفعلي (real-time)** (باستخدام WebSockets أو خدمة مثل Pusher/Ably جنبًا إلى جنب مع Next.js)
- **منصة محتوى بسير عمل نشر قائم على الأدوار** (مسودة ← مراجعة ← نشر)
- **موقع portfolio** باستخدام Cache Components والتوليد الثابت، منشور على Vercel
