## 1. مرحباً بك في كورس Next.js التطبيقي

هذا الكورس يعلّمك Next.js من الصفر باستخدام **App Router**، الطريقة الحالية والموصى بها لبناء تطبيقات Next.js. ستتعلم من خلال بناء كود حقيقي وعملي في كل قسم، لتصل في النهاية إلى أربعة مشاريع تطبيقية.

منهجية التدريس تتبع نمط **المشكلة ← الحل** طوال الكورس: كل درس يبدأ بمشكلة قد تواجهها فعلياً، ويوضح لماذا الحل الساذج غير كافٍ، ثم يقدّم الطريقة الصحيحة في Next.js لحلها.

## 3. متطلبات الكورس المسبقة

يفترض هذا الكورس:

- إتقان قراءة وكتابة **JavaScript أو TypeScript**
- معرفة أساسية بـ **React**: المكونات (components)، الخصائص (props)، الـ hooks (`useState`، `useEffect`)
- لا حاجة لخبرة سابقة في Next.js — سنبدأ من الصفر

إذا كانت React نفسها جديدة عليك، يستحق الأمر قضاء بضع ساعات في أساسيات React أولاً — فـ Next.js يُبنى مباشرة فوق نموذج مكونات React.

## 5. ما هو Next.js؟

### المشكلة

بناء تطبيق React جاهز للإنتاج من الصفر يعني ربط أداة تجميع (bundler)، وموجّه (router)، واستراتيجية عرض (client مقابل server)، وتحسين الصور، وتقسيم الكود، والمزيد — كل هذا قبل كتابة ميزة واحدة.

### الحل

**Next.js** هو إطار عمل (framework) لـ React يوفّر كل هذا جاهزاً: توجيه قائم على الملفات (file-based routing)، عرض من الخادم والعميل معاً، تحسين مدمج للصور/الخطوط/السكربتات، وقواعد لجلب البيانات والتعديلات. أنت تركّز على الميزات؛ Next.js يتولى التفاصيل التقنية.

> 💡 **نصيحة:** Next.js ليس بديلاً عن React — إنه React *بالإضافة* إلى البنية التحتية التي يحتاجها أي تطبيق حقيقي في النهاية.

## 6. Next.js مقابل React

| | React | Next.js |
|---|---|---|
| ما هو | مكتبة واجهات مستخدم (UI library) | إطار عمل متكامل (full-stack) مبني على React |
| التوجيه | يتطلب موجّهاً منفصلاً (مثل React Router) | توجيه قائم على الملفات مدمج |
| العرض (Rendering) | من جانب العميل افتراضياً | Server Components افتراضياً، مع خيارات ساكنة/ديناميكية/تدفقية (streaming) |
| جلب البيانات | لا توجد قاعدة مدمجة | Server Components غير متزامنة (`async`)، تخزين مؤقت، إعادة تحقق (revalidation) |
| منطق الخادم (Backend) | لا يوجد — يحتاج واجهة برمجية منفصلة | Route Handlers و Server Actions مدمجة |
| التحسين | يدوي (إعداد الـ bundler، معالجة الصور) | تلقائي (`next/image`، `next/font`، تقسيم الكود) |

> ⚠️ **تحذير:** لا تفكر في الأمر على أنه "React سيئة، Next.js أفضل". فهما ليسا منافسين — Next.js *هو* React، مع طبقة إطار عمل فوقه.

## 7. متى تستخدم Next.js

يُعد Next.js خياراً قوياً عندما:

- **تحسين محركات البحث (SEO) مهم** — HTML المُعَرَّض من الخادم قابل للزحف وسريع
- تحتاج **منطقاً متكاملاً (full-stack)** — الوصول لقاعدة البيانات، المصادقة، التعديلات — دون إقامة خادم خلفي منفصل
- فريقك يريد إعداداً **جاهزاً ومحدد الرأي (opinionated)** بدلاً من تجميعه من الصفر

وهو أقل ضرورة للتطبيقات التي تعمل بالكامل من جانب العميل (مثل أداة داخلية خلف تسجيل دخول بدون احتياجات SEO)، رغم أن العديد من الفرق تستخدمه هناك أيضاً من أجل تجربة التطوير.

## ✅ ملخص القسم

- Next.js هو إطار عمل لـ React يضيف التوجيه، واستراتيجيات العرض، وقواعد متكاملة (full-stack)
- هذا الكورس يبني المهارات على طبقات عبر 25 قسماً، وينتهي بأربعة مشاريع حقيقية
- المتطلب المسبق: إتقان JS/TS + معرفة أساسية بـ React
- Next.js يتألق في التطبيقات الحساسة لـ SEO والمتكاملة (full-stack)؛ وهو لا يزال React في الأساس

## Review Questions

1. **What is the main difference between React and Next.js?**
   React is a UI library for building components; Next.js is a full-stack framework built on React that adds routing, rendering strategies, data-fetching conventions, and production tooling.

2. **Why might a team choose Next.js over plain React + a router?**
   Because Next.js provides file-based routing, server rendering, image/font optimization, and backend capabilities (Route Handlers, Server Actions) out of the box, removing the need to assemble and maintain that infrastructure separately.
